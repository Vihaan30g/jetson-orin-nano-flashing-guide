1. Overview and objective

The goal of this guide is to take a Jetson Orin Nano whose existing software is old, broken, or unknown, and replace it with a clean, fresh installation of Jetson Linux, an Ubuntu 22.04 based operating system, running from an NVMe SSD. We do not need the existing system to boot at all.

A Jetson is not installed like a laptop. You cannot simply write a generic Ubuntu ISO to it. It needs NVIDIA's own software stack (boot firmware, kernel, drivers, and libraries), prepared and written to it from a separate computer called the host.

The process at a glance

  1. Prepare the host PC: install NVIDIA SDK Manager and its dependencies.
  2. Configure SDK Manager: select the Orin Nano and the required JetPack version.
  3. Download JetPack: fetch the Jetson OS and the NVIDIA components.
  4. Flash the Jetson: erase the existing software and install the new OS.
  5. First boot: connect a monitor and complete the Ubuntu initial setup.

2. The hardware

The board used in this guide has the following specifications:

GPUNVIDIA GPU with 1024 CUDA cores and 32 Tensor Cores
Storage used hereNVMe SSD (already installed)
Software targetJetPack [JETPACK_VERSION] (6.x), Ubuntu 22.04 based

What you need

  • A host PC running Ubuntu 20.04 or 22.04 (x86_64)
  • A reliable internet connection
  • A free NVIDIA Developer account
  • A USB-C data cable (not a charge-only cable)
  • Enough free disk space on the host. NVIDIA recommends at least 27 GB on the host plus 16 GB on the target for a full deployment, depending on the components you select
  • A monitor, keyboard and mouse for the first boot

3. Ways to flash a Jetson

MethodDescription
SDK Manager (used here)NVIDIA's graphical host tool. It guides you through selecting the hardware, downloading software, and flashing. Recommended when flashing directly to an NVMe SSD.
Command-line flashingUsing the Jetson Linux (BSP) package and its flash scripts manually. More control, more steps to learn.

We follow the SDK Manager method because it is the most beginner-friendly, and it handles both downloading and flashing in one guided workflow.

4. SDK Manager and JetPack explained

Why SDK Manager?

Since the Orin Nano cannot be installed from a generic Ubuntu ISO, we need NVIDIA's Jetson Linux software stack and the tools to prepare and flash the board. SDK Manager is the host-side tool that provides this guided workflow.

SDK Manager vs. JetPack

SDK Manager itself is a small application. Once installed, it downloads the much larger JetPack release to the host. JetPack consists of Jetson Linux (the Ubuntu-based OS, kernel, bootloader and NVIDIA drivers) plus optional SDK components such as CUDA, cuDNN, TensorRT and VPI.

          SDK Manager
               |
           Internet
               |
            JetPack
        +------+------+
        |             |
  Jetson Linux   SDK components
  OS, kernel,    CUDA, cuDNN,
  bootloader,    TensorRT, VPI...
  drivers

For a basic OS flash, the mandatory Jetson Linux (BSP) parts are what matter. Optional developer components are not all required, and the video shows which ones to select.

5. Force Recovery Mode

This is the most important concept in the whole process. In a normal boot the board goes through firmware, bootloader, Linux, and then Ubuntu. For flashing we deliberately skip that path:

 Normal boot:
 Power ON -> Firmware -> Bootloader -> Linux -> Ubuntu

 Recovery boot:
 Power ON -> Force Recovery Mode -> USB link to host

Why recovery mode?

The existing OS may be completely broken. In Force Recovery Mode (RCM), the Jetson stops before loading anything from storage and waits for the host over USB. This gives the host low-level access, so it can flash the board regardless of what is installed. NVIDIA requires the developer kit to be in this mode for flashing from a host PC.

Putting the board into recovery mode

With the board powered off, a jumper wire is used to connect the FC REC and GND pins on the carrier board's button header. Connect the USB-C cable to the host, then apply power. Video 3 shows the exact pins and sequence. Check NVIDIA's Developer Kit User Guide if you are unsure about the pin location on your board revision.

Check that the host sees the board

lsusb

An NVIDIA device should appear in the list (usually shown as an APX device). SDK Manager also detects it on its own.

6. Host PC setup and SDK Manager configuration

Preparing the host

On the Ubuntu host, install NVIDIA SDK Manager and its required dependencies, then sign in with your NVIDIA Developer account. Make sure you have enough free disk space for the download, since the JetPack files are large.

Configuring SDK Manager

With SDK Manager open, we tell it exactly what we are doing:

SettingValue
Product categoryJetson
Target hardwareJetson Orin Nano
JetPack versionJetPack 6.x ([JETPACK_VERSION])
Target storageNVMe

In effect, we are saying: "this is the hardware I am flashing, this is the software generation I want, and this is where I want the OS installed." NVIDIA's documentation lists an NVMe SSD as a supported target and recommends SDK Manager for flashing directly to it.

Downloading JetPack

After you accept the licenses, SDK Manager downloads the selected JetPack release to the host. This is the large download of the process, so time depends on your connection. Keep the host awake and online until it finishes.

7. Flashing the NVMe

Now everything is ready: the software is on the host, the Jetson is in recovery mode, and the NVMe is the target.

 HOST PC (Jetson Linux)
       |
       | USB
       v
   Orin Nano
       |
       v
   NVMe SSD  -->  fresh Jetson Linux

The old installation on the target is replaced. Importantly, flashing is more than copying Ubuntu to the SSD. The Orin Nano stores its UEFI boot firmware in QSPI-NOR flash, separate from the NVMe, and that firmware must be compatible with the JetPack release you boot. The process therefore sets up the complete platform: the right boot firmware plus Jetson Linux on the target storage.

Do not interrupt the flash. Keep the USB cable and power connected, and do not put the host to sleep until SDK Manager reports that the installation is complete. Flashing erases the existing contents of the target storage, so back up anything you need first.

8. First boot

After flashing, the Jetson should no longer be in recovery mode: remove the recovery jumper and power-cycle the board. It now boots in the normal sequence from the NVMe:

 Power ON -> Jetson firmware -> UEFI bootloader
          -> NVMe -> Linux kernel
          -> Ubuntu 22.04 based Jetson Linux
          -> Ubuntu first-boot setup

Connect a monitor, keyboard and, if needed, a mouse, and complete the Ubuntu initial setup (language, keyboard layout, time zone, user account and password). Videos 6 and 7 show this in two parts.

9. Verify the installation

Reaching the desktop is a good sign, but it is better to confirm what is actually installed. Open a terminal on the Jetson and check the following.

Ubuntu version

lsb_release -a
cat /etc/os-release

Confirm that the expected Ubuntu release (22.04) is shown.

Jetson Linux release

cat /etc/nv_tegra_release

This is NVIDIA's recommended way to check the installed Jetson Linux release. Compare it with the JetPack version you selected.

Storage

lsblk

The root filesystem (/) should be on an nvme device, which confirms the system runs from the NVMe SSD.

10. Troubleshooting

ProblemLikely cause and fix
SDK Manager does not detect the boardThe board is not in recovery mode, or the cable is charge-only. Use a data cable, connect directly to the host (no hub), and repeat the recovery procedure. Check with lsusb.
Download fails or stopsCheck the internet connection and free disk space, then retry from SDK Manager.
Flashing fails part-wayTry a different USB port or cable, re-enter recovery mode, and run the flash again.
No display on first bootCheck the monitor cable and input, then power-cycle. Confirm the recovery jumper has been removed.
Boot problems after a JetPack changeThe boot firmware in QSPI-NOR must be compatible with the JetPack release. Reflash using the matching release.
